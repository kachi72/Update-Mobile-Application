# Plan 1-004 — Shared RSS Feed Pipeline

**Area:** Android architecture / Networking / RSS / WorkManager / Room  
**Priority:** P1  
**Depends On:** Plan 1-003, existing Room article cache and category Activities

**Objective**

Replace six duplicated feed workers and XML parsers with one configurable RSS pipeline using a shared OkHttp client, a tolerant reusable parser, a repository boundary, and one WorkManager worker.

**Acceptance Criteria**

All six publisher URLs, Room categories, and stable worker keys are defined in one `FeedSource` enum.  
Feed downloads reuse one configured OkHttp client with bounded connection, read, write, and call timeouts.  
Non-successful HTTP responses and missing response bodies are reported as failures, and responses are always closed.  
One namespace-aware parser reads RSS `item` entries using `title`, `description`, `link`, and `pubDate`.  
The parser tolerates CDATA, publisher namespace fields, unknown nested elements, and optional fields.  
The parser supports Atom-style links and reasonable summary, content, date, and GUID fallbacks.  
Invalid entries without a title or usable link are ignored.  
The repository coordinates download, parsing, validation, and Room persistence.  
Existing cached articles are retained when download or parsing fails or returns no valid articles.  
Category deletion and insertion execute in one Room transaction.  
One `ArticleRefreshWorker` accepts the selected feed through WorkManager input data and performs bounded retries for recoverable feed failures.  
All six online category Activities enqueue the generic worker with their corresponding `FeedSource`.  
The six legacy worker/parser implementations are removed with no remaining production references.  
Parser tests cover RSS namespace fields, CDATA, unknown nested content, Atom fallbacks, GUID fallback, and invalid entries.  
MockWebServer tests cover successful downloads and non-successful HTTP responses without contacting live publishers.  
The debug application and Android test APK compile successfully, and local unit tests pass.

**Done When**

Every category refresh uses the same tested network, parser, repository, and worker pipeline while preserving valid cached data on failure and maintaining the existing category UI behavior.

**Validation**

Run `./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest` from the project root.  
Confirm the build and local tests succeed.  
Open each of the six online categories and confirm its articles refresh under the correct Room category.  
Search application sources for the six removed worker names and confirm no production references remain.
