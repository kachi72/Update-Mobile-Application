# Plan 1-003 — Centralized App Executors

**Area:** Android architecture / Concurrency  
**Priority:** P1  
**Depends On:** Plan 1-001 shared Activity changes, existing Room DAO calls, connectivity probes, WebView loading, offline category Activities

**Objective**

Introduce a single application-wide executor provider and replace manually managed background and main-thread dispatch with explicit executors for disk, network, and UI work.

**Acceptance Criteria**

`AppExecutors` is available from the `com.systemtech.update.helpers` package as a thread-safe application singleton.  
Disk operations use an ordered single-thread executor.  
Network operations use a fixed three-thread executor pool.  
UI callbacks use a main-thread executor backed by `Handler(Looper.getMainLooper())`.  
The offline cache check in `MainActivity` uses `diskIO()` and returns navigation or messaging work through `mainThread()`.  
Internet connectivity checks in `MainActivity` and `WebPageActivity` use `networkIO()`.  
WebView configuration and loading return to `mainThread()` before interacting with the view.  
All six offline category Activities read Room data through `diskIO()` and update their views through `mainThread()`.  
Migrated callbacks avoid updating an Activity after it is finishing or destroyed.  
Manual `new Thread(...)` creation and direct main-looper dispatch are removed from migrated call sites.  
WorkManager workers continue using WorkManager-managed background threads without redundant executor nesting.  
Obsolete threading imports are removed from affected files.  
The debug application builds successfully and local unit tests pass.

**Done When**

Database, connectivity, WebView, and UI dispatch in the migrated application flows use the centralized executor provider, with existing behavior preserved and no remaining manual thread creation outside the executor implementation.

**Validation**

Run `./gradlew testDebugUnitTest assembleDebug` from the project root.  
Search application sources for `new Thread`, `Handler`, and `Looper.getMainLooper()` and confirm direct executor construction and main-loop dispatch remain only where intentionally required by `AppExecutors` or framework-managed code.  
Verify offline category navigation, empty-cache messaging, connectivity messaging, and WebView article loading on a device or emulator.
