# Plan 1-002 — Saved Articles and Loading States

## Summary

Redesign Saved Articles and replace the playful Lottie loading treatment so both experiences flow naturally from the new briefing screen and category palette.

## Context

- **Area:** Android UI / Saved Articles / Loading states
- **Priority:** P1
- **Dependencies:** Existing SharedPreferences storage, category gradients, bottom navigation, Material Components, current online/offline layout includes
- **Source:** User direction following the screenshot-led home redesign

## Implementation Plan

1. Replace the photographic Saved Articles background with a soft lavender application surface.
2. Add a rounded lavender-to-mauve header with a saved-item count and concise supporting copy.
3. Add Home, Offline, and Saved bottom navigation with Saved shown as the active destination.
4. Redesign saved article rows as spacious rounded cards with clear category, title, description, and date hierarchy.
5. Apply the matching category gradient to every saved article so the six topics remain visually recognizable.
6. Improve adapter position handling during open and delete actions, consume long-press events, and notify the screen when deletion produces an empty list.
7. Add a styled empty state that fits the new surface and navigation.
8. Replace the online and offline Lottie loaders with compact indeterminate Material progress indicators.
9. Place each loader on a softly elevated rounded surface with formal title and supporting-copy hierarchy.
10. Preserve the existing loading include IDs and Activity show/hide behavior.
11. Build, test, and validate all changed resources and Java code.

## Scope Decisions and Discrepancies

- Saved article colors are category-aware rather than using a single Saved Articles color.
- Existing SharedPreferences persistence and WebView behavior remain unchanged.
- The existing `loading_anim.json` asset remains in the repository for now but is no longer rendered by the shared loaders.
- WorkManager and Room loading behavior remain unchanged; only their presentation changes.
- Per user direction, no `changes` directory or change markdown files are created.
