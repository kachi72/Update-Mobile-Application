# Plan 1-005 — Grouped Layout Resource Roots

## Summary

Organize the flat Android layout collection into feature-focused resource roots while preserving the global `R.layout` namespace and all existing runtime behavior.

## Context

- **Area:** Android project organization / Resources / Gradle
- **Priority:** P2
- **Dependencies:** Existing XML layouts, Android Gradle Plugin resource merging, current Java and XML resource references
- **Source:** User-selected multiple-resource-root approach
- **Target project:** `Update v2/Update`

## Implementation Plan

1. Inventory every layout and every `R.layout` or `@layout` reference before moving files.
2. Add feature resource roots for Home, online categories, offline screens, Saved Stories, reusable cards, loading states, and WebView.
3. Configure the `main` source set to merge the default `src/main/res` directory with all seven layout resource roots.
4. Move `activity_main.xml` into the Home resource root.
5. Move all six online category Activity layouts into the Categories resource root.
6. Move the Offline briefing and all six offline category layouts into the Offline resource root.
7. Move the Saved Stories Activity layout into the Saved resource root.
8. Move article rows, saved article rows, and all six category card includes into the Cards resource root.
9. Move online and offline loading includes into the Loading resource root.
10. Move the WebView Activity layout into the Web resource root.
11. Preserve every resource filename so Java `R.layout.*` and XML `@layout/*` references require no semantic changes.
12. Update README project-structure documentation for the new resource roots.
13. Build, run unit tests, compile Android tests, and run lint to verify resource discovery and merging.

## Scope Decisions and Discrepancies

- Android does not compile arbitrary subdirectories inside `res/layout`, so the organization uses multiple valid resource roots, each containing its own `layout` directory.
- Resource lookup is based on resource type and filename rather than filesystem path. References therefore stay in the form `R.layout.activity_main` and `@layout/loading` after the move.
- The default `src/main/res` root remains configured for drawables, values, XML resources, raw assets, fonts, and mipmaps.
- All resource filenames are unique across the configured roots to avoid merge conflicts between equal-priority resource directories.
- No UI behavior or visual design changes are included.
- Per user direction, no `changes` directory or change markdown files are created.
