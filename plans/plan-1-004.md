# Plan 1-004 — Shared RSS Feed Pipeline

## Summary

Replace six duplicated RSS download/parser workers with one configurable feed pipeline built around a shared OkHttp client, a tolerant reusable parser, a repository boundary, and one WorkManager worker.

## Context

- **Area:** Android architecture / Networking / RSS / WorkManager / Room
- **Priority:** P1
- **Dependencies:** Existing Room article cache, category Activities, WorkManager, Plan 1-003 executor conventions
- **Source:** User direction following review of the six existing feed workers
- **Live feed verification:** All six configured endpoints currently return RSS documents with `<item>` entries and shared `title`, `description`, `link`, and `pubDate` fields; optional namespace fields vary by publisher

## Implementation Plan

1. Add one `FeedSource` enum containing the stable worker key, Room category, and URL for each of the six publishers.
2. Add and reuse one configured OkHttp client for synchronous feed downloads on WorkManager-managed background threads.
3. Treat non-successful HTTP responses and empty bodies as download failures, close every response deterministically, and apply bounded connection, read, write, and call timeouts.
4. Replace the six copies of the XML pull-parser with one namespace-aware SAX parser.
5. Parse RSS `item` entries through the shared `title`, `description`, `link`, and `pubDate` fields while tolerating CDATA, publisher namespaces, unknown nested tags, and optional fields.
6. Support `summary`/`content`, `published`/`updated`, Atom `link href`, and URL-like `guid` values as defensive fallbacks.
7. Add an `ArticleRepository` that coordinates download, parse, validation, and an atomic Room category replacement.
8. Add one `ArticleRefreshWorker` that receives a `FeedSource` key through WorkManager input data and delegates refresh work to the repository.
9. Migrate all six online category Activities to requests created for the generic worker.
10. Delete the six legacy category worker implementations after all call sites use the generic worker.
11. Add local parser tests covering common RSS, publisher namespace fields, unknown nested content, and Atom-compatible fallbacks.
12. Add a MockWebServer test covering successful downloads and non-successful HTTP responses without relying on live publishers.
13. Build, run local tests, lint-check the application, and search for legacy worker references and duplicated feed URLs.

## Scope Decisions and Discrepancies

- The six feeds are structurally compatible at the required article-field level, but not byte-for-byte identical; the shared parser ignores optional publisher fields instead of defining six parsers.
- Retrofit is not added because these endpoints return RSS XML and still require custom parsing; OkHttp provides the useful shared transport layer directly.
- WorkManager continues to own the worker background thread. The repository performs its synchronous network and Room work on that thread rather than nesting `AppExecutors` calls.
- Existing category Activities, Room schema, saved-article persistence, WebView behavior, and UI layouts remain unchanged.
- Existing cached data is replaced only after a download parses at least one valid article, and delete/insert operations run in one Room transaction.
- Network failures retry through WorkManager for bounded attempts; malformed or invalid source input fails without deleting cached articles.
- Per user direction, no `changes` directory or change markdown files are created.
